# 기존 그래프 색인 측정 — 2026-09-13

## 결론

현재 파생 색인을 유지한다. 새 DB가 필요 없다는 증명도, 후보 DB가 더 빠르다는
증명도 아니다. 이번에는 기존 구현만 측정했고, 다른 저장소·모델·렌더러를
설치하지 않았다. 별칭 관련 변경 시나리오의 전체 재읽기가 후속 관찰 대상이다.

1,000·10,000개 합성 문서에서 관계 종류·중복 발생·방향, 현재 리비전 변경,
삭제, 별칭 변경 및 본문 불변 권한 회수를 검사했다. 모두 통과했고 시험 자료는
실행 종료 시 제거했다. 실제 NAS 문서를 복제하거나 수정하지 않았다.
50,000개 규모는 이번 제한된 첫 측정에 포함하지 않았으며 **미실행**이다.
1만 규모의 결과를 5만 규모의 통과 또는 메모리 안전성으로 외삽하지 않는다.

## 방법과 경계

- 명령: `node --max-old-space-size=512 scripts/benchmark-graph-index.mjs --notes 1000`
  또는 `--notes 10000`. 기본값은 1,000개이며 임의 Vault 경로는 받지 않는다.
- 실제 `VaultGraphIndex`, `PathFilter`, `FrontmatterHandler`, `VaultIoCoordinator`와
  bounded reader를 사용했다. 실행은 한 번에 하나, Node v22.23.2였다.
  기존 외부 감독기의 시작 2.3GiB·중단 2GiB 여유 메모리 보호를 유지했다.
- 규모별 새 프로세스·임시 자료를 사용한다. 반환 한도는 40개이며 모델 답변이나
  4,000/12,000자 검색 packet 자체의 성능 측정은 아니다.
- cold는 **메모리 색인 최초 구축**이다. 직전에 생성한 파일의 OS 캐시는 비우지
  않았으므로 cold 디스크·cold NAS 수치가 아니다. dense 자료도 다시 쓴 뒤 읽는다.
- sparse는 문서당 4개 발생, dense는 20개 발생이다. supports·contradicts와
  같은 대상의 두 본문 링크가 모두 남아야 하며 자기 문서의 backlink는 제외한다.
  Properties와 본문을 합쳐 각 1KB 미만인 작은 합성 파일이며 중심 문서/17개
  허브에 연결을 집중시켰다. 실제 장문·PDF·OCR 자료의 분포를 대표하지 않는다.
- 논리 읽기는 실제 bounded-body reader 호출 수와 반환 UTF-8 바이트다.
  stat·metadata·디렉터리 목록·물리 디스크·SMB 바이트와는 다르다.
- 따뜻한 반복 질의는 각각 8회, 나머지 시나리오는 각각 1회다. p50/p95는
  nearest-rank다. **1회 측정의 p95는 그 관측값일 뿐 안정적인 꼬리 지연 추정이
  아니다.** 8회 표본도 운영 부하의 분포를 대표한다고 주장하지 않는다.

## 관측 지연

단위 ms. `p50 / p95`이며 단발 시나리오는 관측값 하나만 적었다.

| 시나리오 | 표본 수 | 1,000문서 | 10,000문서 |
| --- | ---: | ---: | ---: |
| 최초 색인 구축 + 조회 | 1 | 1,590.007 | 13,724.363 |
| 반복 조회 | 8 | 8.443 / 10.106 | 91.617 / 101.829 |
| 문서 하나 갱신 + 조회 | 1 | 22.853 | 134.441 |
| 문서 하나 삭제 + 조회 | 1 | 16.691 | 132.708 |
| 별칭 대상 + 참조 문서 변경 + 조회 | 1 | 720.986 | 7,092.242 |
| 별칭 제거 + 조회 | 1 | 10.313 | 86.034 |
| 같은 predicate의 권한 회수 + 조회 | 1 | 14.512 | 138.114 |
| dense 최초 구축 + 조회 | 1 | 734.401 | 6,534.925 |
| dense 반복 조회 | 8 | 20.842 / 28.865 | 198.971 / 221.711 |

별칭 추가 시나리오는 대상의 별칭과 참조 문서 두 파일을 쓴다. 별칭 하나만의
독립 비용으로 해석하면 안 된다. 이 시나리오에서 거의 전체 자료를 다시 읽은
사실은 관측했으나, watcher 이벤트·재조정·별칭 해석 각각의 인과 비용을
분리했다고 주장하지 않는다. 전체 재읽기를 막기 위해 현재 정합성 검사를
비활성화하지 않았다. 외부 질의 재시도는 두 실행 모두 0회였으며, 색인 내부의
재검사 횟수까지 0이라는 뜻은 아니다.

## 논리 본문 읽기량

각 셀은 `호출 수 / UTF-8 바이트`다. 반복 조회는 8회 합계다.

| 시나리오 | 1,000문서 | 10,000문서 |
| --- | ---: | ---: |
| 최초 구축 | 1,016 / 163,440 | 10,016 / 1,621,440 |
| 반복 조회 | 0 / 0 | 0 / 0 |
| 갱신 | 1 / 30 | 1 / 30 |
| 삭제 | 0 / 0 | 0 / 0 |
| 별칭 대상 + 참조 변경 | 999 / 160,482 | 9,999 / 1,618,482 |
| 별칭 제거 | 1 / 16 | 1 / 16 |
| 권한 회수 | 0 / 0 | 0 / 0 |
| dense 구축 | 1,000 / 480,890 | 10,000 / 4,818,890 |
| dense 반복 | 0 / 0 | 0 / 0 |

프로세스 최대 RSS는 각각 **120.29MiB / 208.43MiB**였다. 서버 전체의 상주
메모리가 아니며 fixture 생성·색인·조회·Node 런타임을 함께 포함한다. 외부
감독기가 기록한 최소 호스트 여유 메모리는 각각 **4.932GiB / 4.624GiB**였다.
메모리 보호 중단이나 제한 완화는 없었다.

## 캐시 한도와 정확성

역방향 캐시 한도는 16,384개다. 1,000문서 sparse 4,000개는 그 아래이고,
dense 20,000개는 그 위다. 10,000문서는 sparse 40,000개와 dense 200,000개
모두 한도를 넘는다. 따라서 1만 규모의 두 결과 차이를 캐시 적중/미적중만의
차이로 해석할 수 없다. private 필드를 조작해 경로를 강제하지 않았으며,
현재 코드의 한도와 실제 합성 자료의 발생 수로 fallback 경로를 확인했다.

각 단계에서 기대 total, supports/contradicts의 존재, 자기 링크 제외, 갱신 전후
SHA256 변경, 삭제 후 발생 수 감소를 검사했다. 별칭을 제거하면 옛 대상의
backlink가 남지 않아야 한다. 권한 회수는 같은 함수 객체가 참조하는 허용 Set만
바꾸며 해당 문서의 본문을 쓰지 않는다. 숨겨진 경로와 그 발생 수는 결과에서
제거돼야 한다. 구조적 관계는 진실·독립 근거·테스트 통과 점수가 아니다.

## 별도 NAS 공유 카운터 관측

기존 공개 문서만 사용하는 읽기 전용 실서비스 검증 전후 약 **7.047초** 동안
Windows SMB 공유 누적 카운터의 read/write bytes, read/write requests,
metadata requests 변화는 모두 0이었다. 실서비스 검증은 통과했고 운영 시험
문서는 만들지 않았다. 이는 **호스트의 해당 공유 전체** 카운터이며 요청별
또는 서버 독점 카운터가 아니다. OS 캐시와 다른 클라이언트가 영향을 줄 수 있다.
0을 논리 NAS 읽기 없음이나 SMB 성능 우수의 증거로 사용하지 않는다.

## 검증과 후속 결정

새 테스트 30개, 인접 그래프 테스트를 포함한 46개 및 strict build가 통과했다.
전체 회귀도 479개 파일·6,745개 통과·실패 0개·기존 조건부 보류 4개로 완료했다.
25개 완료 기록의 파일 범위는 중복·누락 없이 일치했다. 소스·테스트·빌드 기준은
`7f9ea8eb1969443d3815e804b52848b2a1501e85c965897039161ecde8b95c0e`이며 UML
문서·manifest는 별도 입력 지문으로 동결했다. 이전 그래프 런타임의 검증을
새 개발 도구의 전체 통과로 사용하지 않는다.

첫 전체 실행은 메모리 보호로 중단되어 통과 결과에서 제외했다. 같은 기준에서
최대 20파일 단위로 이어 수행한 완료 실행들의 최소 여유 RAM은 4.799GiB였다.
상세 경위와 단독 검토, 변경 없는 실서비스 재확인은
[4·5단계 실행 기록](../plans/2026-09-12-graph-ontology-uml-improvement-proposal.md)에
남겼다. 완료된 성능 측정 자체와 중단된 전체 회귀 시도를 혼동하지 않는다.

후보 저장소의 p95 20% 개선·RSS 비증가·권한/정답 동등성은 **아직 측정하지
않은 채택 기준**이다. 새 저장소 도입은 별도 승인 사항으로 남긴다. 이번
결과는 현재 색인에서 무엇을 먼저 관찰해야 하는지 정한 기초 자료다.
