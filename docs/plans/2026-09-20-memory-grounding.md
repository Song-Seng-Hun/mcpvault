# Ground before applying

`memory.consolidate` remains read-only. Each item separates current bytes,
support readiness, semantic judgment and unverified environment conditions.
Missing/stale support, invalid dates and historical interpretations require review.
Translations with the same exact support set share a source-family identifier.
Mechanical success is not truth, independent evidence or general applicability.

Use existing `wiki.compilation` to pin sources, concepts and output revisions.
Submit a candidate from the current approved session; preserve conditions and
source locators. Existing comparison/fidelity/publication checks remain mandatory.
The existing evolution opportunity bounds one bundle, two candidates and 5 minutes.
No new scheduler, background model, arbitrary shell or automatic external lookup.
Without verified model usage, automatic model work stays off.

## Reversible managed updates

The wiki evolution adapter captures the prior exact bytes only when an earlier
completion receipt proves that the existing output is managed by the same account.
Automatic application also requires this private rollback snapshot.
New documents without an earlier output have no automatic-delete rollback.
They remain manual/review actions, not silently widened automatic permission.
Apply uses the existing checked compilation and verifies its completion receipt.
Reversal checks current authority, source revisions and exact generated output.
It previews a revision-guarded change set, confirms its fingerprint, applies,
then rereads. User edits, changed sources or revoked runtime authority stop it.
After response loss, reconcile actual bytes; do not replay an uncertain patch.
Rollback bytes stay in private host records, never observation logs or packets.

Example: a supported exception added to an existing managed lesson can qualify;
rewriting an immutable source, disputed fact or user preference cannot.
Actual next-session use and effect remain distinct from apply/revert tests.
