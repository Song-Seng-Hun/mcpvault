# 1. Content contract

Three separate layers: preserved bytes, current verified body, discovery card.
A short card never substitutes for source evidence or a complete translation.
General notes/manuals become real chapter files; old paths become outlines.
Service records keep IDs, statements, state and storage; expose read chapters.
Code, commands, quotes, error strings, licenses and original bytes stay exact.

## Chapter envelope

Maximum 50 physical lines including metadata/blanks; target 20-40.
Never evade limits with huge lines; oversized semantic units become source reads.
Include stable document/chapter IDs, title, description, kind/domain/purpose,
use/avoid conditions, intent/project, verified bilingual aliases and provenance.
Include parent/previous/next, position, prerequisite/counterpoint/tool references.
Pin source revision/locator, rule version and status. Links are not authority.
Manual/tool chapters include short positive and refusal/exception examples.
Large outlines recurse. Reading order differs from semantic relatedness.
Default chapter response 2000 chars; packet 4000; explicit expansion <=12000.
Count the entire envelope and model tokenizer input, not just body length.
Preserve tables/fences/footnotes/YAML; incomplete reads carry continuations.

## Language and expression

Use concise English, stable terms, one fact/instruction per sentence.
Preserve negation, qualifiers, uncertainty, causality, numbers and units.
No invented abbreviations or deliberately broken grammar. Clarity wins.
Use English (한국어); Korean UI instructions use 한국어 (English).
Each independently read chapter repeats necessary names at first occurrence.
Unknown English names remain Korean. Aliases bind entity/project/version.
Same name does not establish identity. Translations share one source family.
Caveman source is pinned licensed reference; Vault expression is an adaptation.
No upstream compress scripts, external model calls or original overwrite.
Presentation profile never edits character memory, world state or past speech.

## Precedence

System/host/current ACL/original protection > approved absolute rules >
applicable project defaults > Vault defaults > style/examples.
Project defaults cannot weaken prohibitions. Equal-rank conflicts need review.
Editable priority/absolute fields never establish authority. Enforce in services.
